## 一、AI Agent 基础认知

### 1.1 定义
AI Agent = 可观察环境、执行行动以达成目标的智能实体，支持通过AI优化自身性能

### 1.2 发展历程
```
传统LLM（问答） → 早期LLM Agent（ReAct框架/GPT-4） → 本地LLM Agent（Llama/Qwen） → 下一代AI Agent（OpenClaw）
```

### 1.3 核心架构
- **ReAct框架**：Reason + Act（推理 + 行动）
- **四大模块**：输入、思维、交互、记忆
- **核心能力**：工具调用、互联网访问、代码解释、自主决策

### 1.4 Agent 类型
| 类型 | 说明 |
|------|------|
| 单Agent | 独立执行 |
| 多Agent | 协同交互 |
| 人机协作 | Agent + 人类 |
| 简单反射型 | 基于规则 |
| 模型基型 | 基于内部模型 |
| 目标基型 | 目标导向 |
| 效用基型 | 效用最大化 |

### 1.5 记忆模块设计
- 基于**黑板理论**
- System Prompt 锁定人设
- Context Management 优化历史记录
- OpenClaw 采用**本地 Markdown 文件**存储 → 透明化编辑 + 隐私安全

## 二、OpenClaw 底层架构深度解析

### 2.1 整体定位
- 开源可定制的**长期在线AI员工系统**
- 与 Claude Code 差异化：**瑞士军刀 vs 手术刀**（非竞争关系）

### 2.2 核心架构三大组件

```
┌─────────────────────────────────────────┐
│              OpenClaw 架构               │
├─────────────┬──────────┬────────────────┤
│ Agent Loop  │  Tools   │   Gateway      │
│  （大脑）    │ （手脚） │  （身体）       │
├─────────────┼──────────┼────────────────┤
│ 思考→调工具  │ 基础工具 │ 常驻在线       │
│ →检查结果    │ Skills   │ 20+渠道对接    │
│ →判断下一步  │ 外部工具 │ 会话隔离       │
│ →循环直到完成│          │ 排队控制       │
│             │          │ 心跳巡查       │
│             │          │ 记忆刷盘       │
└─────────────┴──────────┴────────────────┘
```

### 2.3 Agent Loop 详解
- AI自主完成任务的**核心循环机制**
- 流程：思考 → 调工具 → 检查结果 → 判断下一步 → 循环
- 基于开源 Pi SDK 开发
- 与 Claude Code、Codex **核心逻辑一致**

### 2.4 Tools 三层体系

| 层级 | 说明 | 示例 |
|------|------|------|
| **基础工具** | 读写文件、执行命令、网页浏览 | read、write、exec、web_fetch |
| **Skills** | 沉淀人类工作经验 | 项目扫描、文件备份、报告生成 |
| **外部工具** | 调用外部API、SaaS服务 | MCP服务器、第三方API |

### 2.5 Gateway 六大核心能力

| 能力 | 说明 |
|------|------|
| **常驻在线** | 故障自恢复，7×24小时运行 |
| **多平台对接** | 20+渠道消息统一适配（飞书/Telegram/Discord等） |
| **会话隔离** | 不同对话互不干扰 |
| **排队控制** | 避免并发冲突 |
| **心跳巡查** | 主动执行 + 定时调度（Heartbeat + Cron） |
| **记忆刷盘** | 关键信息防丢失 |

## 三、多 Agent 协作架构

### 3.1 三种运行时模式

| 运行时 | 用途 | 适用场景 |
|--------|------|---------|
| **main** | 主会话，直接与用户交互 | 日常对话、简单任务 |
| **subagent** | 隔离的子Agent | 复杂任务分解、并行处理 |
| **acp** | ACP编程会话 | 代码开发、调试、测试 |

### 3.2 多 Agent 架构优势

- **并行处理**：多个子Agent同时执行独立任务
- **任务隔离**：每个子Agent独立context，避免信息污染
- **灵活扩展**：按需创建，完成后自动清理
- **错误隔离**：单个失败不影响其他

### 3.3 核心工具

#### sessions_spawn（创建子Agent）
```json
{
  "task": "分析项目代码结构",
  "runtime": "subagent",
  "label": "代码分析",
  "mode": "run"
}
```

关键参数：
| 参数 | 说明 |
|------|------|
| runtime | subagent / acp |
| mode | run（一次性）/ session（持久） |
| label | 标签，用于识别 |
| task | 任务描述 |
| thread | true 则绑定消息线程 |
| streamTo | "parent" 可流式输出到父会话 |

#### subagents（管理子Agent）
- list：列出所有子Agent
- steer：向子Agent发送指令
- kill：终止子Agent

#### sessions_yield（让出控制）
- 启动子Agent后使用，等待结果返回

### 3.4 任务编排模式

#### 模式1：串行执行
```
主Agent → 子Agent A → 等待结果 → 子Agent B → 等待结果 → 汇总
```

#### 模式2：并行执行
```
主Agent → 同时启动子Agent A/B/C → sessions_yield → 收集所有结果 → 汇总
```

#### 模式3：流水线
```
子Agent A输出 → 作为子Agent B输入 → 作为子Agent C输入 → 最终结果
```

## 四、Plugin 开发

### 4.1 Skills 系统
- Skills = 沉淀人类工作经验的可复用模块
- 存储在 `~/.openclaw/skills/` 目录
- 每个Skill包含 `SKILL.md`（说明文件）+ 脚本/模板

### 4.2 Skill 结构
```
my-skill/
├── SKILL.md          # 技能说明（触发条件、使用方法）
├── scripts/          # 执行脚本
│   └── main.py
├── references/       # 参考资料
│   └── api-docs.md
└── templates/        # 模板文件
    └── output.md
```

### 4.3 SKILL.md 关键字段
```yaml
---
name: my-skill
description: 技能描述（用于自动匹配触发）
allowed-tools: Bash(my-skill:*)
---

# 技能标题

## 使用方法
...

## 约束
...
```

### 4.4 外部工具（MCP）
- 通过 MCP（Model Context Protocol）协议接入外部服务
- 支持 HTTP 和 stdio 两种通信方式
- 配置在 `.openclaw/config.yaml` 中

## 六、核心观点总结

### 💡 关键认知

1. **Agent 核心竞争力不在底层模型，而在记忆连续性 + 自主决策能力**
2. 底层模型可灵活切换且不影响核心体验
3. OpenClaw 无算法级突破，但**模块高效封装 + 协同运行** = 实用落地
4. 产品创新不止于技术突破，**场景落地 + 模块稳定运行**同样是核心竞争力
5. AI技术的价值在于实际应用，**先使用再优化**
