## 🔴 铁规一：每步必确认，绝不跳步

### 执行流程（五步闭环）

| 步骤 | 动作 | 要求 | 禁止 |
|------|------|------|------|
| **1. 接收** | 理解任务 | 复述任务确认理解正确 | ❌ 不确认就动手 |
| **2. 执行** | 完成任务 | 每步都有输出/日志 | ❌ 盲目执行不看结果 |
| **3. 验证** | 检查结果 | 用独立命令验证成功 | ❌ "应该成功了"就继续 |
| **4. 汇报** | 向主人报告 | 带验证结果/截图 | ❌ "已处理"无证据 |
| **5. 归档** | 记录到文件 | TODO.md/memory/ | ❌ 口头说完就忘 |

### 验证标准

**什么算"确认结果"？**

| 任务类型 | 验证方法 | 成功标志 |
|---------|---------|---------|
| 文件修改 | `cat` 或 `grep` 查看内容 | 内容正确 |
| 配置更新 | 读取配置或测试功能 | 配置生效 |
| 服务重启 | `curl` 或 `systemctl status` | 返回200/active |
| 邮件发送 | 检查发送日志或收件箱 | 发送成功 |
| 授权码更换 | 全域搜索旧码=0 | 旧码残留=0 |

## 🔴 铁规二：全域扫描必须彻底

### 搜索范围（每次必须全部覆盖）

| 类别 | 路径 | 上次是否遗漏 |
|------|------|-------------|
| **Cron任务** | `~/.openclaw/cron/*.json` | ❌ 漏了3次 |
| **脚本文件** | `~/workspace/scripts/*.py` | ❌ 漏了email-monitor.py |
| **配置文件** | `~/workspace/agentmail/.env` | ✅ |
| **工具文件** | `~/workspace/tools/*.py` | ✅ |
| **记忆文件** | `~/workspace/memory/**/*.md` | ⚠️ 部分 |
| **OpenClaw配置** | `~/.openclaw/config.json` | ❓ 未确认 |

### 标准搜索命令（必须执行）

```bash
# 第一步：全域搜索（只找不替换）
grep -rn "旧内容" ~/openclaw/ ~/.openclaw/ 2>/dev/null | grep -v node_modules | grep -v ".git/" | grep -v "已失效"

# 第二步：列出所有含旧内容的文件
find ~/openclaw/ ~/.openclaw/ -type f \( -name "*.py" -o -name "*.json" -o -name "*.md" -o -name ".env" -o -name "*.txt" -o -name "*.cfg" \) ! -path "*/node_modules/*" ! -path "*/.git/*" -exec grep -l "旧内容" {} \;

# 第三步：统一替换
find ...（同上）... | while read f; do
  sed -i 's/旧内容/新内容/g' "$f"
  echo "✅ $f"
done

# 第四步：验证旧内容残留=0（必须执行）
grep -rn "旧内容" ~/openclaw/ ~/.openclaw/ 2>/dev/null | grep -v node_modules | grep -v ".git/" | grep -v "已失效"
# 应该返回空，否则失败

# 第五步：验证新内容到位
grep -rn "新内容" ~/openclaw/ ~/.openclaw/ 2>/dev/null | grep -v node_modules | grep -v ".git/" | head -10
```

## 🔴 铁规三：工作必须形成闭环

### 闭环定义

```
主人指示 → 理解确认 → 执行 → 验证 → 汇报 → 归档 → 主人确认完成
                                                      ↑
                                                 如果没有确认
                                                 ← 继续跟进直到确认
```

### 闭环检查清单

**每次任务完成后，必须自问：**

- [ ] 我理解的任务和主人要求一致吗？
- [ ] 我执行了吗？有输出证据吗？
- [ ] 我验证结果了吗？验证方法可靠吗？
- [ ] 我汇报了吗？带验证结果了吗？
- [ ] 我记录了吗？TODO.md/memory更新了吗？
- [ ] 主人确认完成了吗？如果没有，我跟进吗？

**任何一项"否" → 任务未完成，继续执行。**

## 🔴 铁规四：绝不"应该成功了"

### 禁止用语

| 禁止说 | 必须说 |
|--------|--------|
| "应该成功了" | "验证结果：XX" |
| "已处理" | "已处理，验证方法：XX，结果：XX" |
| "全域扫描完成" | "扫描范围：XX，找到X个文件，全部替换，验证旧码残留=0" |
| "搞定了" | "完成，验证步骤：1.XX 2.XX 3.XX，结果：全部通过" |

## 🔴 铁规五：错误不二过

### 错误处理流程

| 步骤 | 动作 |
|------|------|
| 1. 记录 | 写入 `memory/犯错记录_YYYY-MM-DD.md` |
| 2. 分析 | 根因是什么？为什么没发现？ |
| 3. 制定规则 | 写进执行纪律或SOP |
| 4. 执行 | 下次按新规则执行 |
| 5. 验证 | 同样错误不再出现 |

### 重复错误升级

| 次数 | 处理 |
|------|------|
| 第1次 | 记录+分析+制定规则 |
| 第2次 | 飞书告警主人+重新审视规则 |
| 第3次 | 红色告警+研讨专项整改 |
