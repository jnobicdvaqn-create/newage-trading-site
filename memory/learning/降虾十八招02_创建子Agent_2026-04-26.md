## 一、核心内容（实事求是记录视频原文）

### 1.1 为什么要创建子Agent

> "当一个任务特别复杂的时候，如果只有一个Agent来处理，流程会变得非常长，它的上下文也会因为塞入太多的东西而变得非常的冗长，就可能会出现幻觉。"

**类比：** 一个人什么事情都亲历亲为，整天忙碌，最后会导致焦头烂额出现幻觉。

### 1.2 解决方案：分工思想

> "这个时候最好的办法是把任务分配出去。这些也就是程序中常说的分工思想。我们把任务分解成一个小块，让每个子Agent单独去执行。"

### 1.3 子Agent的好处

| 好处 | 说明 |
|------|------|
| **独立上下文** | 每个子Agent都有自己独立的上下文 |
| **独立背景** | 每个子Agent有独立的系统指令 |
| **独立工具** | 每个子Agent可以使用自己的工具集 |
| **上下文干净** | 主Agent不需要关心具体如何完成，上下文保持简洁 |

### 1.4 工作模式

> "主Agent负责任务分解，然后依次创建和调用每个子Agent，完成任务之后回到主任务，主任务再去创建下一个子Agent，依次完成任务。"

**流程图：**
```
主Agent
  ↓ 任务分解
子Agent 1 → 独立上下文/背景/工具 → 执行完成 → 返回结果
  ↓
子Agent 2 → 独立上下文/背景/工具 → 执行完成 → 返回结果
  ↓
子Agent 3 → 独立上下文/背景/工具 → 执行完成 → 返回结果
  ↓
回到主Agent
```

### 1.5 重要注意：阻塞式调用

> "这里我们并没有做到异步处理，目前的Agent实际上是阻塞了。当主Agent在调用子Agent的时候，它会停下来等待，直到子Agent的返回结果，再去调用下一个。"

**不是异步：** 主Agent等待子Agent完成后才继续下一个

### 1.6 如何创建子Agent

> "这就是我们第一招里讲到的创建和调用工具。实际上你可以把它看作是一个工具调用的过程。"

**创建方法：**
1. 创建一个函数，在函数内部再次调用大模型（子Agent）
2. 子Agent有自己独立的消息队列
3. 预设最大循环次数（防止死循环）
4. 子Agent调用工具完成任务
5. 最终结果返回给主Agent

### 1.7 本质：一切都是工具调用

> "本质上就是一个简单的工具调用。我们需要一个函数，大模型能够看懂的接口。我们把这个接口告诉大模型，大模型自己会决定什么时候调用这个函数，什么时候创建子Agent。"

**与第一招一模一样：** 子Agent本质上也是一个工具

### 1.8 扩展工具示例

可以定义更多工具给大模型：
1. **创建子Agent** — 分配复杂任务
2. **读取文件** — 在系统里读文件
3. **写入文件** — 在系统里写入文件
4. **修改文件** — 修改文件内容

> "有了这四个接口之后，我们就可以开始进行交互式的Write Code。这四个函数已经完全够了。"

### 1.9 重要原则：最小干预

> "在与大模型的交互过程中，人类的参与应该是最小化，人的参与越少效果可能反而越好。只要把任务梳理清楚，尽量不用管大模型，一切交给它来调度。"

**核心原则：**
- 任务梳理清楚
- 最小化人工参与
- 一切交给大模型调度

## 二、关键概念总结

| 概念 | 说明 |
|------|------|
| **任务分解** | 复杂任务拆分成小块，交给子Agent |
| **上下文隔离** | 每个子Agent独立上下文，避免冗长 |
| **阻塞调用** | 主Agent等待子Agent完成后继续 |
| **工具调用** | 子Agent本质上也是一个工具 |
| **最大循环次数** | 防止子Agent死循环 |
| **消息队列** | 子Agent有独立的消息队列 |
| **最小干预** | 人类参与越少，效果越好 |
