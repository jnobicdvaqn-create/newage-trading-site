## 一、核心内容（实事求是记录视频原文）

### 1.1 问题：同步任务效率低

> "前面讲的各种任务管理，这些任务都是阻塞的。横序只有一个进程，运行时间只能跑一个任务。当一个任务完成之后，才可以运行下一个任务。整体是一个串行的过程。"

### 1.2 解决方案：多线程异步

> "我们可以在程序中创建多个线程，让这些任务可以并行地去跑。"

### 1.3 主要框架

```
主线程 → Agent决策和思考
  ↓ 遇到耗时任务
创建后台任务 → 独立线程运行
  ↓ 主线程不等待
继续执行主线程任务
  ↓
后台任务完成 → 结果放入消息队列
  ↓
主线程定时查看消息队列 → 提取消息 → 清空队列 → 放入上下文决策
```

### 1.4 三个工具接口

| 接口 | 功能 |
|------|------|
| Run接口 | 创建并运行后台程序 |
| Check接口 | 查询所有后台任务的状态 |
| 获取消息 | 从消息队列里面提取消息 |

### 1.5 关键：公共资源加锁

> "由于是异步执行，我们需要对这些公共资源加上锁。因为任务状态和消息队列是公共资源，我们对它们进行操作时，特别是改写的时候，需要加上锁，以免多个线程同时对它们继续操作。"

### 1.6 核心原则

> "我们只是提供这类工具给它，让它自己做决策。这就是整个Agent开发的整体思路。"

## 二、关键概念总结

| 概念 | 说明 |
|------|------|
| **异步 vs 同步** | 同步=串行阻塞，异步=并行非阻塞 |
| **后台任务** | 独立线程运行，主线程不等待 |
| **消息队列** | 后台任务完成后结果放入队列 |
| **锁机制** | 公共资源（任务状态/消息队列）需要加锁 |
| **三个工具** | Run（创建后台）、Check（查状态）、GetMessage（取消息） |
| **主线程循环** | 查消息队列→提取→上下文决策→继续 |
