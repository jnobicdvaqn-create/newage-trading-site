## 一、核心内容（实事求是记录视频原文）

### 1.1 问题：上下文无限膨胀

> "随着多轮对话，上下文窗口包含所有的输入、模型的输出、以及调工具的结果等等。随着次数增多，整个上下文会变得非常的混乱，而且它的大小会急速的扩张。"

**三个问题：**
1. 模型上下文有最大限制，不能无限塞入
2. 上下文越长，模型能力会有边际递减
3. Token数和成本会增加

### 1.2 三层压缩技术

#### 第一层：去掉历史工具调用结果

> "在原始的对话流中，可以去掉一些工具调用的结果，只保留最近的工具调用结果，把历史的工具调用结果给去掉。"

**原因：** 工具调用的结果大模型看过之后，后面可能就不会再用到。而且工具输出有时特别长（如命令行报错信息）。

**方法：** 找到历史记录，除保留最近的工具调用结果外，把历史结果替换成占位符（如"这个结果已经被清除掉了"）。

**保护机制：** 读文件/加载Skill的内容不清除（后续还会用到，清除后大模型会再次请求加载，造成浪费）。

#### 第二层：LLM自动总结压缩

> "当Token数大于一定程度的时候，我们可以利用AI来自动总结，让大模型把大量的信息进行压缩总结，提取它的关键信息。"

**方法：**
1. 把历史信息保留到硬盘上（先记录下来）
2. 把这段历史信息交给大模型
3. 大模型自己去总结压缩
4. 大模型决定哪些信息被压缩，哪些保留

#### 第三层：大模型主动请求压缩

> "让大模型自己去决定什么时候去压缩。如果大模型自己觉得它的上下文太乱，它会根据自己的需求主动要求调用压缩工具来对自己进行压缩。"

### 1.3 完整流程

```
Agent进入循环
  ↓
第一步：低层压缩（去掉历史工具输出结果）
  ↓
判断Token数 > 50%上下文？
  → 是：手动调用压缩工具（LLM总结历史消息）
  → 否：继续执行
  ↓
执行任务过程中，大模型自己觉得上下文乱
  → 主动请求调用压缩函数
```

### 1.4 三个总结原则

1. **选择性遗忘**：不是所有信息都值得记住，尤其是工具输出结果，用完就忘记
2. **压缩前保留**：对信息进行压缩之前，应该把原始信息保留到硬盘
3. **保护重要内容**：读文件/加载Skill/重要信息需要完整保留

### 1.5 未来发展方向：Memory

> "未来的发展可能更像Memory的方式，把历史信息放在文件或者数据库里面，并且写入名字和摘要。当我们后面需要的时候，可以让大模型自动的把历史信息按照分类的结果找回来，把相关的历史信息再次拉回到模型的上下文中。"

> "我们可以参考Memory的方式去创建Memory，并且加入索引。把Skill这套技术拿过来，来管理我们的上下文历史，把它变成另外一种Skill。当我们需要的时候，再去请求加载我们的历史。"

## 二、关键概念总结

| 概念 | 说明 |
|------|------|
| **三层压缩** | 低层清理 → LLM总结 → 大模型主动压缩 |
| **选择性遗忘** | 工具输出用完即忘，只保留最近结果 |
| **占位符替换** | 历史工具结果替换为"已清除"占位符 |
| **保护机制** | 读文件/加载Skill的内容不清除 |
| **50%阈值** | Token超过50%上下文时触发自动压缩 |
| **硬盘保留** | 压缩前先把原始信息保存到硬盘 |
| **Memory方向** | 历史信息→文件/数据库→索引→按需加载 |
