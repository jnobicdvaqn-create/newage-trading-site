## 一、核心内容（实事求是记录视频原文）

### 1.1 什么是Skill

> "Skill实际上是Prompt Engineering的一个体现。"

> "我们之前用大模型的时候，每个人都要自己去写Prompt。同样一个大模型，为什么有的人用得好，有人又不好呢？是我们写Prompt的Skill不一样。"

> "Skill本身实际上就是一段提示词。"

### 1.2 Skill标准化定义

**函数标准化定义（Python）：**
- 函数名字
- 描述
- 输入参数

**Skill标准化定义（Markdown）：**
- 名字
- 描述（给大模型看，告诉大模型这个Skill是关于什么内容）

### 1.3 Skill文件格式

**主流方法：Markdown文件格式**
```
---
name: 技能名称
description: 技能描述（给大模型看）
---

Skill正文内容...
```

### 1.4 Skill目录化

> "我们有一个通俗的约定，比如说我们创建一个Skill的文件夹，下面可以创建子文件夹，单独存储各个独特的Skill。"

**标准结构：**
```
skills/
  ├── skill-a/
  │   └── SKILL.md
  ├── skill-b/
  │   └── SKILL.md
  └── skill-c/
      └── SKILL.md
```

### 1.5 Skill中插入工具接口

> "你也可以在Skill中插入工具接口。比如说在某个Skill的时候，它可能会附带了两个工具。只要把这两个工具的描述以及它对应的接口放在Skill文件里面。"

### 1.6 Skill加载流程

**步骤一：搜索所有Skill.md**
> "我们会定义一个函数加载所有的Skill，它会在这个路径下面去搜索所有的SKILL.md文件。"

**步骤二：解析头部**
> "如果找到这样的文件，它就会把头部和正文分解开来。在头部中取到它的名字和它的描述。"

> "解析头部主要用到的就是一个正则表达式，这个正则表达式就是把这三个横杠中间的所有内容给提取出来。"

**步骤三：转换为JSON**
> "把它提取完之后，我们可以用冒号把这些信息转换成JSON的格式。"

### 1.7 Skill按需加载

> "Skill是按需加载的方式。如果你需要很多技能和任务，你不可能一次性地把所有的Skill全部加载到模型的上下文里，这样会特别消耗Token。"

**加载流程：**
1. 只把Skill的名字和描述放在系统提示词里
2. 大模型根据需求调用工具加载需要的Skill
3. 加载后放到上下文里

### 1.8 Skill本质

> "整个Skill的加载实际上就是工具的调用，只是Skill它本身并没有可执行的工具，它只提供一段文本，也就是上下文交给大模型。"

## 二、关键概念总结

| 概念 | 说明 |
|------|------|
| **Skill本质** | 一段提示词（Prompt Engineering） |
| **标准化格式** | Markdown + YAML头（---name/description---） |
| **目录化** | skills/子文件夹/SKILL.md |
| **按需加载** | 只加载名字和描述到系统提示词，需要时再加载正文 |
| **Token节省** | 不一次性加载所有Skill正文 |
| **工具接口** | Skill可附带工具描述和接口 |
| **正则解析** | 用正则表达式提取YAML头内容 |
