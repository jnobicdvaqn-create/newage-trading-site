## 🎥 视频1：探索OpenClaw龙虾的记忆机制，打通记忆链路

**BV号：** BV1JMosBVEk6 | **时长：** 15分钟 | **转录：** 353行

### 核心知识点

#### 一、记忆完整性检查
- 打开OpenClaw配置管理器 → 记忆管理页面 → 点击"诊断"
- 全绿 = 记忆通路畅通
- 红色报错 = 记忆功能不完整

#### 二、OpenClaw记忆四层架构

| 层级 | 类比 | 说明 |
|------|------|------|
| **模型底层记忆** | 大脑训练 | 模型预训练阶段获得的能力 |
| **短期记忆** | 电脑内存(RAM) | 会话上下文窗口，关机后消失 |
| **长期记忆** | 电脑硬盘 | 跨会话持久存储 |
| **外挂记忆** | 外接存储 | 扩展的长期记忆（单独分类） |

#### 三、模型底层记忆
- 模型能力来源于训练阶段记忆的内容
- 不同底座模型效果天差地别
- 后训练阶段的人类对齐（RLHF）影响回复风格
- 回复模式在训练阶段已固定，无法根本改变
- 可用提示词缓解风格问题

#### 四、短期记忆（上下文窗口）
- 只存在于单个会话中
- 类似电脑内存，关机后消失
- 受模型上下文窗口大小限制
- 重要内容需要及时保存到长期记忆

#### 五、免费模型福利
- **CodeBuff** 提供免费模型服务
- 需要GitHub账号登录获取凭证
- 支持模型：GPT-5.1-max等
- GPT-4o-2.7和GPT-3.5-turbo已不可用
- 可能遇到限流排队

## 🎥 视频2：龙虾可视化配置管理器

**BV号：** BV1gUSZBzEBH | **时长：** 29分钟 | **转录：** 738行

### 核心知识点

#### 一、Provider（提供商）管理

**概念类比：**
- Provider = 银行（工商银行/农业银行）
- Base URL = 银行地址
- API Key = 银行卡密码

**国内主流Provider：**
- 豆包、MiniMax、Kimi、DeepSeek等

**API协议类型：**

| 协议 | 来源 | 说明 |
|------|------|------|
| openai_completion | OpenAI | 标准协议，兼容最广 |
| openai_responses | OpenAI | 新协议，Codex使用 |
| anthropic_messages | Anthropic | Claude专用 |
| google | Google | Gemini专用 |

**配置步骤：**
1. 登录Provider开放平台创建API Key
2. 在配置管理器 → Provider管理 → 添加
3. 填写：Provider Key名称、API Key、Base URL
4. 选择正确的API协议类型
5. 测试连通性
6. 获取可用模型列表

#### 二、Agent模型配置
- 为不同Agent分配不同模型
- 配置后通常无需重启Gateway即可生效
- 如未生效需重启Gateway

#### 三、Skill管理
- 可视化配置管理Skill
- 支持启用/禁用Skill
- 支持Skill版本管理

#### 四、自动备份功能
- 支持本地和远程机器备份
- 远程登录仅支持SSH密钥认证（不支持密码输入）

#### 五、远程机器管理
- **Linux查看IP：** `ifconfig` 或 `ip addr`
- **Linux查看用户名：** `whoami`
- **Windows查看用户名：** `whoami`
- **SSH登录要求：** 必须配置SSH密钥免密登录
- **前提条件：** 本地公钥已添加到远程机器 `~/.ssh/authorized_keys`
