## 核心内容（实事求是记录视频原文）

### 核心结论

> "OpenClaw千万别急着重新安装。真正该搬的不是一套新安装，而是旧机器上那套已经能工作的运行环境。"

### 常见错误

> "很多人一上来就想重新部署一遍，但这一步最终把时间浪费在补环境、补插件、补连接上。"

### 核心原则

> "迁移不是安装，是搬运现场。"

### 四步迁移法

| 步骤 | 动作 | 关键点 |
|------|------|--------|
| **第一步：停服务** | 停止Gateway服务 | 先把现场冻结住 |
| **第二步：打包** | 打包OpenClaw相关目录 | 边运行边备份会夹着变化中的状态文件 |
| **第三步：传输** | 备份传输到新机器 | 相关目录一次带走，别拆着搬 |
| **第四步：恢复检查** | 准备环境→解压→Fix→重启Gateway→Status检查 | 按恢复流程走 |

### 关键注意事项

| 问题 | 解决方案 |
|------|---------|
| **服务起不来** | 最常见是权限归属不一致（不同用户打包和恢复） |
| **修复方法** | 先修正目录所有者，再看服务状态 |
| **上线前检查** | 确认新服务器网络权限和磁盘空间到位 |
| **恢复后操作** | Doctor → Restart → Status |
| **删除旧备份** | 备份确认没问题之前不要急着删 |

### 顺序原则

> "顺序不要乱，越按这个节奏走，迁移后的环境就越接近原来的状态。"

```
停Gateway → 打包OpenClaw目录 → 传输 → 新机器准备环境 → 解压 → Fix → 重启Gateway → Status检查
```

## 关键概念总结

| 概念 | 说明 |
|------|------|
| **搬运现场** | 迁移不是重新安装，是搬运能工作的运行环境 |
| **冻结现场** | 先停服务再打包，避免夹着变化中的状态文件 |
| **一次带走** | 相关目录整体打包，不要拆分 |
| **权限归属** | 不同用户打包和恢复时最常见的问题是文件所有者不一致 |
| **Doctor→Restart→Status** | 恢复后标准检查流程 |
