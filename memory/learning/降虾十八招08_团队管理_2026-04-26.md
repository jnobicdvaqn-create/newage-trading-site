## 一、核心内容（实事求是记录视频原文）

### 1.1 主题

> "如何让Agent自己管理一个团队。管理一个团队主要涉及到如何去调度团队成员，以及如何进行通信。"

### 1.2 消息通信：邮箱系统

**底层实现：** 每个人的邮箱对应一个JSON文件

**三个接口：**
| 接口 | 功能 |
|------|------|
| 发送消息 | 由发送者发给目标人，写入对应文件 |
| 读取消息 | 按照自己的名字读取自己邮箱内容 |
| 广播消息 | 向所有人群发一条信息（除了自己） |

### 1.3 团队管理：HR系统

**三个对外接口：**
| 接口 | 功能 |
|------|------|
| 派生/激活 | 大模型决定何时激活队员，设定角色和任务内容 |
| 列出团队成员及状态 | 了解团队规模、成员忙碌程度 |
| 查询成员状态 | 谁在忙、谁在空闲 |

### 1.4 派生队员的状态转移

```
空闲/下班 → 被激活（新建线程）→ 更新状态为忙碌
  → 调用工具完成任务 → 发送消息给相关人
  → 更新状态为空闲/下班
```

**如果成员正在忙：** 返回状态给大模型，大模型重新指派另一个人

### 1.5 三类工具

| 类别 | 示例 |
|------|------|
| **基本工具** | bash命令、文件读写修改 |
| **团队管理工具** | 激活成员、分配任务、查询空闲状态 |
| **通信工具** | 读取信息、发送信息、广播消息 |

### 1.6 整体流程

```
主Agent启动 → 等待用户输入
  ↓
读取邮箱（团队成员反馈）
  ↓
逻辑推理决策
  ↓
是否调用工具？
  → 是：调用三类工具之一
  → 否：生成回应等待下次指令
  ↓
根据工具反馈结果→再次逻辑判断
  ↓
决定继续调用工具 or 反馈用户
  ↓
循环往复
```

## 二、关键概念总结

| 概念 | 说明 |
|------|------|
| **邮箱系统** | JSON文件存储，每人一个邮箱文件 |
| **HR调度** | 大模型决定何时激活谁、派什么活 |
| **状态中心** | 记录每个成员状态（空闲/忙碌/下班） |
| **广播机制** | 群发消息给所有成员（除自己） |
| **状态转移** | 空闲→激活→忙碌→完成→空闲 |
| **三类工具** | 基本操作+团队管理+通信 |
