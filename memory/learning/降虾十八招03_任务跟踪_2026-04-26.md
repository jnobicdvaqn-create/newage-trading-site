## 一、核心内容（实事求是记录视频原文）

### 1.1 问题：Agent在漫长上下文中迷失

> "有时候我们要设计一个Agent对一个特别复杂的任务，我们希望Agent会把这个任务拆成多部来完成。Agent的首席可能会把这个任务规划成上千部。"

> "在茫茫的上下文中迷失自己，可能不知道自己执行到哪一步了，也不知道哪一步已经完成，哪些还有做。"

### 1.2 解决方案：任务跟踪

> "我们需要不停的提醒Agent他已经做了哪些任务，哪些任务还需要去做，让他随着任务一步一步来完成，不要太混乱。"

### 1.3 方法：上下文注入

> "对于大模型来讲，我们只有一个办法，就是通过上下文中加入信息来提醒，控制他的唯一办法就是在上下文中注入信息，影响他的逻辑和行为。"

**具体做法：**
- Agent列出多个任务后
- 每次执行完一个任务，在上下文中插入包含ID、状态标识等信息
- 明确标注哪些任务已完成、哪些正在进行、哪些还没有开始

### 1.4 效果

> "这种做法能让大模型在执行过程中不但通过上下文自我提醒，了解当前所处的阶段，比如当前正处在第三步，下一步应该执行第四步。"

### 1.5 如何定时产生提醒信息

**方法：万能的第一招——调用工具**

> "我们只需要定义一个工具让Agent去调用。这个工具其实就是一个函数，它的输入是一个步骤或者任务的一个列表。"

**函数逻辑：**
1. 遍历任务列表
2. 查看每个任务的状态（ID、完成情况）
3. 这些参数由Agent传递进来
4. 函数只做简单的任务统计
5. 生成统计结果返回给大模型

**生成的文本格式：**
```
一共有四个任务
哪些任务已经完成
哪些任务正在进行
哪些任务还在等待完成
```

### 1.6 如何强迫Agent调用状态更新工具

**问题：** Agent会偷懒，觉得没有必调用

**解决方法一：计数器强制**
> "在主程序中设计一个变量，记录它调用其他工具的次数。如果连续多次忽视了状态更新函数，比如说这里是四次，我们就在消息队列里面插入专门的提示，要求大模型立即调用这个工具更新自己的状态。"

> "若大模型继续忽略，我们就不断地加入这条消息，直到这个函数得到执行。我们把计数器清零，然后开始再次计数。"

**解决方法二：系统提示词**
> "在系统级别的提示词中加入这个信息。在系统提示词中明确告诉大模型，每个几次必须调用一次状态更新函数。"

> "系统提示词的优先级非常高，在模型的整个计算过程中注意力值非常大，因此模型通常会严格遵守这些指令。"

### 1.7 实际问题：模型偷懒

> "比如我让模型生成9个步骤并跟踪状态。开始时它能正常写第一步已经完成，其他的还在等待。第二步也是如此。"

> "但是执行到第三步，调用函数的时候，它就开始偷懒，只在参数里面传入了当前的一个任务，后续也是一直传一个任务。"

**解决方案：**
> "需要在提示词或者在函数的描述里面更加清晰地告诉大模型，加入参数的时候必须要包含所有的任务，而不能只传当前执行的任务。"

### 1.8 调试心得

> "调试Agent有时非常难，因为模型出错的方式非常智能，而且非常容易偷懒。要调试好一个Agent有时候的确需要丰富的经验和下苦力。"

## 二、关键概念总结

| 概念 | 说明 |
|------|------|
| **上下文迷失** | 任务步骤太多，Agent不知道自己到哪一步了 |
| **上下文注入** | 在消息队列中插入状态信息来提醒Agent |
| **状态跟踪工具** | 一个函数，接收任务列表，返回统计结果 |
| **计数器强制** | 连续N次不调用状态更新→强制插入提示 |
| **系统提示词** | 最高优先级指令，强制模型定期调用工具 |
| **模型偷懒** | 只传当前任务而不是全部任务列表 |
| **参数完整性** | 提示词中必须明确要求传所有任务 |
