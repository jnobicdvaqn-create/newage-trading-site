## 一、核心内容（实事求是记录视频原文）

### 1.1 问题：任务依赖管理

> "大模型对于很复杂的任务会规划出多个子任务来完成。前置任务之间可能会有相互依赖。比如说任务二和任务三都依赖于任务一，任务四依赖于任务二和任务三。"

### 1.2 本质：拓扑排序

> "任务之间的依赖问题实际上是一个有向无环图。在力扣里面有一类题目叫拓扑排序，就是处理这类任务管理的问题。"

### 1.3 四个工具接口

| 接口 | 功能 |
|------|------|
| 创建任务 | 大模型创建新任务 |
| 更新任务状态 | 更新某个任务的状态 |
| 获取某个任务 | 查询单个任务状态 |
| 获取所有任务状态和依赖关系 | 查询全部 |

### 1.4 任务存储：文件系统状态思想

> "把任务存储在一个文件系统里面或者是数据库里面。这里是一种文件系统状态的思想，也就是把任务以文件的形式保存下来。有文件就说明有任务，没有文件就没有任务。"

### 1.5 核心机制：前置条件自动清除

> "当大模型对任务状态进行更新的时候，但它发现一个任务已经完成，它需要调用一个函数来告诉其他的任务，特别是依赖这个任务的其他任务，来对任务依赖的前置条件进行更新。"

> "比如说任务一已经完成，它会告诉任务二和任务三，把任务一从任务二和任务三的前置条件中移除掉。这样的话，任务二和任务三就可以被大模型激活，可以去执行这些任务。"

### 1.6 两类工具

| 类别 | 说明 |
|------|------|
| **任务管理工具** | 任务创建、状态更新、查询所有/单个任务 |
| **执行任务的工具** | 某些任务需要的工具（如执行bash命令、读写硬盘、修改文件） |

### 1.7 工作流程

```
大模型决策和思考
  ↓
收到用户需求
  ↓
自动创建任务→存储到任务状态数据库中
  ↓
读取可执行的任务→调用工具完成任务
  ↓
更新任务状态→清除依赖关系
  ↓
选择下一个任务→继续完成
  ↓
如此往复循环
```

### 1.8 核心原则

> "对于Agent的开发来说，我们只要定义好接口给大模型，至于什么时候调用、如何调用、输入的参数是什么，这一切都会交给大模型自己来做决定。"

> "工具是提供给大模型使用的，它会根据上下文自己做出逻辑判断。这是Agent开发中非常重要的一点。"

## 二、关键概念总结

| 概念 | 说明 |
|------|------|
| **拓扑排序** | 有向无环图，处理任务依赖 |
| **前置条件** | 任务依赖的前置任务列表 |
| **自动清除** | 前置任务完成后自动从依赖列表中移除 |
| **任务池** | JSON文件存储所有任务状态 |
| **文件系统状态** | 有文件=有任务，无文件=无任务 |
| **激活机制** | 前置条件全部完成后任务被激活可执行 |
| **两类工具** | 任务管理工具 + 执行任务工具 |
