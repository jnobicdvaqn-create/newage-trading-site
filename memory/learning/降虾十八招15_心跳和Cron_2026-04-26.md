## 核心内容

### 心跳机制（Heartbeat）

> "心跳本质上就是一个类似死循环的机制。每隔一秒醒来一次，查看是否有待执行的任务，执行后再次进入睡眠。"

**运行流程：**
```
休眠中醒来 → 检查运行条件（时间段）→ 检查主线程空闲
  ↓ 条件满足
查看任务列表 → 调用Agent处理 → 结果写入消息队列
  ↓ 释放资源
再次睡觉 → 等待下一轮检查
```

### Cron计划任务

- 按预设时间执行任务（类似闹钟）
- 格式：`分 时 日 月 星期` 五个星号

### 关键区别

| 特性 | Heartbeat | Cron |
|------|-----------|------|
| **触发方式** | 固定频率（如30秒一次） | 绝对时间点（如每周一9:30） |
| **主线程忙时** | 跳过，等下次心跳再试 | 必须完成，每秒尝试直到空闲 |
| **风格** | 没事不打扰 | 到了必须做 |
| **作用** | 赋予Agent自主意识 | 赋予Agent工作流程 |

> "没有心跳的Agent只是工具，有了心跳的Agent才是真正的助理。"

### 与现有系统关联

| 概念 | 我们的实现 |
|------|-----------|
| Heartbeat | OpenClaw heartbeat机制 ✅ |
| Cron | crontab定时任务 ✅ |
| 非干扰 | 主线程空闲检查 ✅ |
| 任务队列 | 消息队列 ✅ |
