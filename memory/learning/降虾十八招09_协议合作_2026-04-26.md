## 一、核心内容（实事求是记录视频原文）

### 1.1 问题：主从Agent缺乏交互

> "主Agent分配任务之后就不再过问，子Agent只是埋头苦干。两者之间缺乏交互。子Agent执行任务后直接提交结果就下线，结果的质量、下线的时机、是否符合主Agent的初衷都无法得到确认。"

### 1.2 解决方案：握手协议

> "让团队成员与主Agent通过握手协议达成一致，在任务执行前后保持交互。"

### 1.3 协议一：计划审批协议

**流程：**
```
子Agent开始执行任务
  ↓ 制定任务计划
发邮件请求主Agent审批
  ↓
主Agent定期检查邮箱→发现请求→调用大模型评估计划
  ↓
计划可行 → 批准 → 邮件通知子Agent → 开始执行
计划不可行 → 拒绝 → 子Agent修改计划 → 重新请求
```

**如何实现：**
- 系统提示词中明确要求：执行前必须提交审批计划
- 提供"请求计划审批"工具接口

### 1.4 协议二：关机协议

**流程：**
```
主Agent任务完成→发邮件请求子Agent下线
  ↓
子Agent定期检查邮箱→发现关机请求
  ↓
确认执行关机步骤
  ↓
发消息告诉主Agent已下线
  ↓
状态改为"关机"
  ↓
主Agent确认
```

### 1.5 接口定义

**主Agent接口：**
| 接口 | 功能 |
|------|------|
| 计划审批工具 | 审批子Agent提交的计划（批准/拒绝） |
| 发起关机请求 | 通知子Agent下线 |

**子Agent接口：**
| 接口 | 功能 |
|------|------|
| 请求计划审批 | 提交计划并等待批准 |
| 响应关机请求 | 确认并执行关机 |

### 1.6 核心原则

> "整个流程的核心在于通过接口的定义，由大模型自主决策，决定调用逻辑。"
