## 一、核心内容（实事求是记录视频原文）

### 1.1 工具调用整体架构

**视频主题：** 万能的工具 (Tool Use) — 拆解Agent如何让大模型学会"用工具"

### 1.2 五个核心步骤

#### 步骤一：工具映射（Mapping）

> "我们要把名字映射到函数的接口上。当大模型输出名字的时候，我们可以通过这个映射关系直接找到函数的入口。"

| 概念 | 说明 |
|------|------|
| 映射表 | 工具名称 → 函数入口 |
| 用途 | 根据LLM返回的名字找到对应函数 |

#### 步骤二：工具列表（Tool List）

> "如果有多个函数供大模型参考，我们要把它放到一个列表里面。每一个函数的第一项都是遵循这种规则。然后把这个列表交给大模型。"

- 每个函数定义遵循统一规则（JSON Schema格式）
- 打包成列表发给大模型
- 每次调用都要发送工具列表

#### 步骤三：大模型决策

> "大模型会读取这个列表，并根据你的输入要求，决定去调用哪个函数，同时会给出调用函数的参数值。"

- LLM读取工具列表
- 根据用户需求决定调用哪个工具
- 返回：工具名称 + 参数值

#### 步骤四：主程序执行

> "当我们的主程序收到大模型的返回之后，我们需要进行判断是不是有工具使用。如果使用工具，那么我们就从这个映射表中通过返回的名字来取得函数的入口，并且调用函数。"

- 主程序解析LLM返回内容
- 判断是否有工具调用
- 通过映射表找到函数入口
- 执行函数，传入参数

#### 步骤五：结果回传

> "最后我们把调用的结果打包返回给大模型。这里我们必须要附上它的ID，因为大模型可能会一次产生很多个工具的使用。通过这个ID，大模型就能匹配到对应的结果。"

- 结果打包回传LLM
- **必须附带ID**（匹配多工具调用）
- LLM根据结果生成最终回答

### 1.3 宏观流程（六大环节）

```
┌─────────────────────────────────────────────────┐
│ 1. 函数接口 → JSON格式（大模型可识别的定义）        │
│ 2. 建立映射表（名字 → 函数入口）                    │
│ 3. 打包工具列表发给大模型                          │
│ 4. 大模型返回工具名称+参数                         │
│ 5. 主程序调用函数，结果回传                         │
│ 6. 大模型生成最终回答                              │
└─────────────────────────────────────────────────┘
```

**关键点：** 接口转化问题 — 把程序可以看到的函数定义，转成大模型可看的定义。因为大模型本身是文本处理器，没有结构化信息，需要把函数转成JSON格式。

### 1.4 ReAct模型（推理+行动循环）

> "整个Agent实际上就是一个ReAct模型。它首先会调用大模型进行思考和行动。如果大模型返回没有行为（即Reason不再调用工具），就会直接退出。"

**ReAct = Reason + Act**

```
思考(Reason) → 行动(Act) → 观察结果 → 再思考 → 再行动 → ... → 不再行动 → 结束
```

### 1.5 双循环机制

**内循环（推理循环）：**
- Agent内部推理循环
- 思考 → 行动 → 观察 → 再思考

**外循环（用户交互循环）：**
- 等待用户输入 → 加入消息队列 → 启动Agent → 执行内循环 → 退出 → 等待下一次输入

```
┌─ 外循环 ─────────────────────────────┐
│  等待用户输入                          │
│  ↓                                    │
│  ┌─ 内循环 ───────────────┐            │
│  │  调用LLM思考            │            │
│  │  ↓                      │            │
│  │  有工具？→ 是 → 执行     │            │
│  │  ↓ 否                   │            │
│  │  退出内循环              │            │
│  └────────────────────────┘            │
│  ↓                                    │
│  等待下一次用户输入                     │
└──────────────────────────────────────┘
```

### 1.6 实例演示

**工具定义：** shell命令执行工具（屏蔽危险命令）

**演示流程：**
1. 定义shell执行函数 → 转成LLM可识别的接口
2. 建立映射表（名字 → 函数）
3. 定义Agent（系统指令：使用shell解决问题）
4. 消息队列循环开始
5. 判断是否有工具可用 → 有则执行 → 无则返回

**实际操作：**
- 用户指令："创建一个文件夹，在下面创建一个Python文件打印Hello World"
- LLM返回四条指令：创建文件夹 → 进入文件夹 → 写入Python语句 → 执行
- 每次执行shell → 结果返回LLM → LLM再次决策
- 最终得到完整结果

## 二、关键概念总结

| 概念 | 说明 |
|------|------|
| **工具映射** | 名字 → 函数入口，用于LLM返回时定位函数 |
| **工具列表** | JSON格式的工具定义，每次调用LLM都要发送 |
| **调用指南** | LLM返回的内容：工具名称 + 参数值 |
| **ID匹配** | 多工具调用时，用ID匹配结果与调用 |
| **ReAct模型** | Reason(推理) + Act(行动) 的循环 |
| **双循环** | 内循环(推理) + 外循环(用户交互) |
| **消息队列** | 存储对话历史，每次调用LLM时包含完整历史 |
