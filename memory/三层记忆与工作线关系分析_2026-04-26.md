## 一、两条线的本质区别

### 1.1 定义对比

| 维度 | 三层记忆编码机制 | 工作任务线 |
|------|----------------|-----------|
| **本质** | 知识沉淀系统 | 任务执行系统 |
| **目标** | 长期价值、知识积累 | 短期价值、任务完成 |
| **导向** | 查询检索、经验复用 | 执行推进、进度追踪 |
| **载体** | memory/ + memory_store | TODO.md |
| **周期** | 长期（月/年） | 短期（日/周） |
| **产出** | 报告/笔记/决议 | 任务完成状态 |
| **编码** | 知识编码（L-/R-/K-） | 任务编码（T-/D-） |

### 1.2 功能对比

**三层记忆（知识沉淀）：**
```
热记忆（session实时）
    ↓ 每日归档
暖记忆（memory/文件）
    ↓ 向量写入
冷记忆（memory_store向量库）
    ↓ 关键词检索
知识复用
```

**工作任务线（任务执行）：**
```
任务启动（TODO.md P0）
    ↓ 执行推进
进度追踪（状态更新）
    ↓ 完成验收
产出沉淀（写入memory/）
    ↓ 进入记忆系统
```

### 1.3 核心差异

| 差异点 | 记忆线 | 工作线 |
|--------|--------|--------|
| **时间维度** | 历史+未来（沉淀+复用） | 现在（执行推进） |
| **价值维度** | 知识资产 | 执行效能 |
| **检索维度** | 关键词+向量+编码 | 状态+优先级+负责人 |
| **更新频率** | 低（每日归档） | 高（实时更新） |
| **告警机制** | 无（知识无逾期） | 有（三级逾期升级） |

  经验积累         关键词检索      复用支撑

  下一轮任务 ←←←←←←←←←←←←←←←←←←←←←← 知识支撑执行

### 2.2 联系机制

## 三、如何落实：区别+联系+协调

### 3.1 区别落实（不混用）

**铁规一：两条线分开管理**

| 管理维度 | 记忆线 | 工作线 |
|---------|--------|--------|
| **载体** | memory/ + memory_store | TODO.md |
| **更新** | 每日归档（cron） | 实时更新（heartbeat） |
| **告警** | 无告警机制 | 三级逾期升级 |
| **检查** | heartbeat检查产出 | heartbeat检查进度 |
| **编码** | 知识编码（L-/R-/K-/M-） | 任务编码（T-/D-/R-） |

**禁止混用：**
- ❌ 记忆线任务进入TODO.md P0
- ❌ 工作线产出不写入memory/
- ❌ 记忆线有逾期告警
- ❌ 工作线无编码标注

### 3.2 联系落实（自动关联）

**铁规二：产出自动沉淀**

| 工作产出 | 沉淀动作 | 记忆编码 |
|---------|---------|---------|
| 任务完成报告 | 写入memory/reports/ | R-REP-XXX-YYYY-MM-DD |
| 学习笔记 | 写入memory/learning/ | L-XXX-NN-YYYY-MM-DD |
| 研讨决议 | 写入memory/supervision/ | D-XXX-NNN-YYYY-MM-DD |
| 研究员报告 | 写入memory/researcher/ | R-REP-N-YYYY-MM-DD |

**自动触发机制：**
```
任务完成 → 检查产出类型 → 写入对应memory/ → 编码标注 → memory_store写入
```

**代码示例：**
```python
# 任务完成时自动触发
if task.status == "COMPLETED":
    if task.output_type == "report":
        write_to_memory("reports", task.output)
        add_keywords(task.output, task.keywords)
        memory_store(task.summary, task.keywords)
```

### 3.3 协调落实（统一编码）

**铁规三：编码体系统一**

| 编码类别 | 编码格式 | 适用场景 | 示例 |
|---------|---------|---------|------|
| **任务编码** | T-[模块]-NNN-[状态] | TODO.md任务 | T-SEC-001-P |
| **决议编码** | D-[类别]-NNN | TODO.md决议 | D-S-002 |
| **报告编码** | R-[类别]-NN-YYYY-MM-DD | memory/reports/ | R-SEC-01-2026-04-26 |
| **学习编码** | L-[主题]-NN-YYYY-MM-DD | memory/learning/ | L-MOQ-02-2026-04-21 |
| **研究员编码** | R-REP-N-YYYY-MM-DD | memory/researcher/ | R-REP-07-2026-04-25 |

**编码关联规则：**
```
T-SEC-001-P（任务） → 完成后 → R-SEC-01-2026-04-26（报告）
D-S-002（决议） → 执行后 → L-S-002-2026-04-26（学习笔记）
```

## 四、具体落实方案

### 4.1 记忆线独立管理

**载体：** memory/ + memory_store
**更新机制：** 三层同步cron（Micro/Daily/Weekly）
**检查机制：** heartbeat检查产出（无告警）

**管理动作：**
1. 每日归档：session → memory/文件
2. 每周蒸馏：memory/ → memory_store
3. 每月清理：冷记忆清理无价值内容

**关键词标注：** 所有文件≥3个关键词

### 4.2 工作线独立管理

**载体：** TODO.md
**更新机制：** heartbeat实时检查（三级逾期升级）
**检查机制：** 每次heartbeat扫描P0/P1状态

**管理动作：**
1. 实时更新：任务状态变更
2. 逾期告警：三级升级机制
3. 阻塞处理：Plan B自动启动

**编码标注：** 所有任务有编码

### 4.3 联系机制自动化

**自动触发点：**

| 触发事件 | 自动动作 | 验证方法 |
|---------|---------|---------|
| 任务完成 | 写入memory/ | 检查memory/文件 |
| 研讨结束 | 写入决议+决议编码 | 检查TODO.md决议 |
| 学习结束 | 写入笔记+关键词 | 检查memory/learning/ |
| 研究员汇报 | 写入报告+关键词 | 检查memory/researcher/ |

**验证机制：**
- 任务完成 → 检查memory/是否有对应产出
- 研讨结束 → 检查TODO.md是否有决议编码
- 学习结束 → 检查memory_store是否有写入

### 4.4 self-improving-agent协调

**与三层记忆的协调点：**

| 协调维度 | self-improving-agent | 三层记忆 |
|---------|---------------------|---------|
| **错误学习** | 记录错误+改进建议 | memory_store写入 |
| **经验沉淀** | 分析改进案例 | memory/learning/写入 |
| **机制优化** | 提出流程改进 | memory/supervision/写入 |

**协调流程：**
```
self-improving-agent检测错误
    ↓
写入memory_store（错误+改进）
    ↓
下次执行前memory_recall查询
    ↓
应用改进建议
    ↓
避免重复错误
```

## 六、总结

**区别：**
- 记忆线：知识沉淀系统（长期、查询导向）
- 工作线：任务执行系统（短期、完成导向）

**联系：**
- 工作产出 → 自动沉淀 → 记忆系统
- 记忆系统 → 知识复用 → 支撑执行

**落实三铁规：**
1. 区别：两条线分开管理，不混用
2. 联系：产出自动沉淀，编码关联
3. 协调：统一编码体系，self-improving协调

**预期效果：**
- 记忆线完整沉淀知识资产
- 工作线高效推进任务执行
- 两条线互相关联，知识支撑执行
