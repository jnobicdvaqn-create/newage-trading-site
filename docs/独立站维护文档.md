### 4.2 getStaticPaths 模式

所有 `[lang]` 页面都使用相同的模式：

```ts
export function getStaticPaths() {
  return [
    { params: { lang: 'en' } },
    { params: { lang: 'ru' } },
    { params: { lang: 'zh' } },
  ];
}
```

动态页面（`[id]`, `[slug]`, `[pair]`, `[scenario]`, `[country]`）则通过 `flatMap` 展开：

```ts
export function getStaticPaths() {
  return langs.flatMap(lang =>
    products.map(product => ({
      params: { lang, id: product.id },
      props: { product, lang },
    }))
  );
}
```

## 六、i18n 国际化系统

### 6.1 三层翻译架构

```
┌─────────────────────────────────────────────────────────┐
│ 第1层：UI翻译（translations.json）                        │
│ t('nav.cars', lang) → "汽车出口" / "Автоэкспорт"         │
│ 用途：导航、按钮、标题、表单标签等固定UI文案                   │
├─────────────────────────────────────────────────────────┤
│ 第2层：数据翻译（JSON数据文件）                             │
│ tData(car, 'name', 'zh') → car.nameZh                    │
│ 用途：产品名称、描述、特性等产品级内容                        │
├─────────────────────────────────────────────────────────┤
│ 第3层：内联翻译（页面内硬编码）                              │
│ lang === 'zh' ? '联系我们' : lang === 'ru' ? '...' : '...'│
│ 用途：复杂场景（FAQ、步骤说明、表格等）                      │
└─────────────────────────────────────────────────────────┘
```

### 6.2 核心函数

| 函数 | 位置 | 用途 | 示例 |
|------|------|------|------|
| `t(key, lang)` | `@i18n/index.ts` | 查找translations.json中的翻译 | `t('nav.cars', 'zh')` → "汽车出口" |
| `tData(obj, key, lang)` | `@lib/i18n-data.ts` | 从对象中提取多语言字段 | `tData(car, 'name', 'zh')` → `car.nameZh` |
| `tArr(obj, key, lang)` | `@lib/i18n-data.ts` | 提取多语言数组字段 | `tArr(product, 'features', 'zh')` → `product.featuresZh` |
| `label(key, lang)` | `@lib/i18n-data.ts` | UI标签快捷查找 | `label('home', 'zh')` → "首页" |
| `getTranslations(lang)` | `@i18n/index.ts` | 获取完整翻译对象 | 用于复杂数据访问 |

### 6.3 hreflang 标签

BaseLayout 自动生成三语 `hreflang` 标签：

```html
<link rel="alternate" hreflang="en" href="https://newage-trading.com/en/cars/" />
<link rel="alternate" hreflang="ru" href="https://newage-trading.com/ru/cars/" />
<link rel="alternate" hreflang="zh" href="https://newage-trading.com/zh/cars/" />
<link rel="alternate" hreflang="x-default" href="https://newage-trading.com/en/cars/" />
```

### 9.2 ⚠️ 容易出错的地方（重点标记）

#### 1. 修改数据文件后必须重新构建

```bash
# ❌ 错误：修改了JSON文件但没有构建
vim src/data/cars.json
git push
# → VPS上的dist/仍然是旧版本

# ✅ 正确流程：
vim src/data/cars.json        # 1. 修改源数据
npx astro build               # 2. 重新构建
git add src/data/ dist/       # 3. 提交源数据+构建产物
git commit -m "..."           # 4. 提交
git push origin master:main   # 5. 推送
```

#### 2. 图片路径与文件名必须精确匹配

- `cars.json` 中的 `image` 字段值（如 `/images/cars/byd-han.jpg`）必须与 `public/images/cars/` 下的文件名完全一致
- **区分大小写！** Linux文件系统区分大小写，Windows/Mac可能不区分
- 新增产品时必须同时添加图片和更新JSON

#### 3. 翻译键必须三语一致

- 在 `translations.json` 中新增翻译键时，**必须同时在 `en`、`ru`、`zh` 三个语言下添加**
- 缺少任一种语言 → 该语言页面显示翻译键本身（如 `nav.cars`）
- **验证方法：** 构建后分别访问 `/en/`、`/ru/`、`/zh/` 页面

#### 4. getStaticPaths 必须覆盖所有语言

- 每个 `[lang]` 页面必须返回 `en`、`ru`、`zh` 三个 `getStaticPaths`
- 动态路由页面（`[id]`、`[slug]`）必须用 `flatMap` 展开所有语言×所有数据

#### 5. 图片缓存版本号

- 每次替换图片内容后，**必须**更新 `?v=` 参数或改文件名
- 当前版本号：`20260514` / `20260514b` / `20260514c`
- 下次更新用：`20260515` 或 `20260514d`

#### 6. security-products.json 缺少 category/type 字段

- 截至 2026-05-14，`security-products.json` 中 **26款产品全部缺少 `category` 和 `type` 字段**
- security 列表页使用 `security.json`（而非 `security-products.json`）作为数据源
- **不要混用这两个文件！**
- `security.json`：用于列表页，有 `category` 和 `type` 字段
- `security-products.json`：用于产品详情页，有 `name/nameZh/nameRu`、`features/featuresZh/featuresRu` 等

#### 7. 涉密文件绝对不可推送

- **禁止推送的文件/目录：** `memory/`, `agents/`, `tools/`, `SOUL.md`, `MEMORY.md`, `HEARTBEAT.md`, `TODO.md`, `TOOLS.md`, `USER.md`, `IDENTITY.md`

## 十四、维护操作指南

### 14.1 添加新博客文章

```bash
# 1. 编辑 blog-posts.json，添加新文章对象
vim src/data/blog-posts.json

# 2. 下载封面图到 public/images/blog/
curl -L "unsplash-url" -o public/images/blog/new-article.jpg

# 3. 构建验证
npx astro build
ls dist/en/blog/  # 确认新页面已生成

# 4. 提交推送
git add src/data/blog-posts.json public/images/blog/new-article.jpg dist/
git commit -m "feat: add new blog article: [标题]"
git push origin master:main

# 5. 等待VPS同步（2-5分钟），curl验证
curl -s -o /dev/null -w "%{http_code}" https://newage-trading.com/en/blog/[id]/
```

### 14.2 添加新汽车产品

```bash
# 1. 编辑 cars.json
vim src/data/cars.json

# 2. 添加产品图片
cp new-car.jpg public/images/cars/new-car.jpg

# 3. 更新缓存版本号（cars.json 中 image 字段加 ?v=新版本）
# 或修改 ProductCard.astro 中的版本号

# 4. 构建+提交
npx astro build
git add src/data/cars.json public/images/cars/ dist/
git commit -m "feat: add new car model: [型号]"
git push origin master:main
```

### 14.3 添加翻译键

```bash
# 1. 在 translations.json 中三语同时添加
vim src/data/translations.json
# 确保 en/ru/zh 三个顶层对象中都有新键

# 2. 构建验证
npx astro build
# 分别访问 /en/ /ru/ /zh/ 确认翻译正常

# 3. 提交推送
```

### 14.4 修改联系方式

参考 **第十章**，同步修改 **6个文件**，然后构建+推送。

### 14.5 图片替换

1. 替换 `public/images/` 下的文件
2. **必须更新缓存版本号**（`?v=` 参数）
3. 构建 + 提交
4. VPS 同步后验证
